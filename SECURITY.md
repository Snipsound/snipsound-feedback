# Security Policy

## Reporting a security issue

Please **do not** publish suspected security vulnerabilities as public GitHub issues.

A public report could expose SnipSound users before the problem can be investigated and fixed.

Use the repository's private **Report a vulnerability** option if it is available. If private vulnerability reporting is not available, contact SnipSound privately through its existing support channel and include only enough information to establish contact. Do not post exploit instructions, credentials, tokens, private user data, or sensitive logs publicly.

## Public bug reports

Ordinary product bugs that do not involve a security risk can be submitted through the public bug-report form.

Before posting, remove:

- Passwords, API keys, access tokens, cookies, and session identifiers
- Private audio, video, transcription, or text-to-speech content
- Personal or confidential information
- Local file paths and private URLs
- Files you do not have permission to share
